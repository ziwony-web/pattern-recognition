# 뉴스 인기 예측 프로젝트 이해 가이드

이 문서는 기존 과제와 2026-10-14 유지보수 실험을 구분해서 이해하기 위한 가이드입니다. 새 코드는 AI의 도움을 받아 정리한 코드이며, 당시 직접 구현한 작업으로 소개하지 않습니다.

## 1. 무엇을 예측했나?

기사의 제목·본문 길이, 링크·이미지 수, 키워드 통계, 주제 분포, 감성 점수, 채널·요일 등을 보고 인기 기사인지 분류합니다. 기사 원문을 언어모델에 입력하는 방식이 아니라, 이미 수치와 범주로 정리된 표를 사용하는 머신러닝 프로젝트입니다.

- 한 행 = 기사 한 건.
- 입력 X = 46개 원본 특성. 원-핫 인코딩 후 열 수는 더 늘어날 수 있습니다.
- 정답 y = 공유 수가 1,400회를 **초과**하면 1, 그렇지 않으면 0.
- train: 22,200행 × 49열. id, shares, y를 제외하면 46개 입력 특성입니다.
- test: 9,515행 × 47열. id와 입력 특성이 있고, shares/y는 없습니다.

실제 CSV에서 shares=1,400인 901개 행의 정답은 모두 0입니다. 따라서 `>=1400`이라고 설명하면 이 데이터와 맞지 않습니다.

## 2. 왜 shares를 입력에서 빼야 하나?

정답이 shares로 결정되는데 모델에 shares를 보여주면 이미 답을 알려준 셈입니다. 이것이 정답 누출입니다. id도 기사 식별 번호이므로 예측 특성에서 제외합니다. 반면 `self_reference_*_shares`는 다른 참조 기사 관련 통계 이름이며, 현재 기사 정답 shares와는 구분합니다. 이런 통계가 실제 예측 시점에도 얻을 수 있는지는 별도의 데이터 출처 검토가 필요합니다.

## 3. 전처리는 무엇을 했나?

원래 과제에서는 특성별 결측치 대체, 원-핫 인코딩, 일부 실험의 1–99% 분위수 클리핑 등을 시도했습니다. 현재 비교용 기준 모델은 구성을 단순화했습니다.

1. 먼저 train을 학습 17,760건과 검증 4,440건으로 나눕니다.
2. 수치 결측치는 **학습 부분의 중앙값**으로 채웁니다.
3. 범주 결측치는 Unknown으로 채우고 원-핫 인코딩합니다.
4. 검증과 test에는 학습 때 정한 변환을 그대로 적용합니다.

예를 들어 학습 자료의 이미지 수 중앙값이 2라면 검증 자료의 빈칸도 2로 채웁니다. 검증 자료를 보고 새 중앙값을 구하지 않습니다. Pipeline은 이 전처리와 모델을 하나로 묶어 같은 순서를 적용합니다. 원본 과제의 전처리 전체를 그대로 재현한 것은 아닙니다.

## 4. Random Forest와 XGBoost의 차이

Random Forest는 서로 다른 데이터 표본과 특성 선택으로 여러 결정트리를 만들고 예측을 모읍니다. 한 트리의 불안정한 판단을 평균화하는 방식입니다.

XGBoost는 앞선 모델의 오차를 줄이는 방향으로 트리를 순서대로 더합니다. 학습률, 트리 깊이, 정규화 등을 조절해 복잡도를 관리합니다. 두 모델 모두 신경망이 아닌 트리 기반 모델입니다.

이번 설정은 과거 실험 기록을 참고해 고정했으며, 새 검증 점수가 가장 좋게 나오도록 다시 탐색하지 않았습니다. 과거 탐색에 사용한 데이터와 겹칠 수 있으므로 완전히 처음 보는 최종 평가라고 말하지 않습니다.

## 5. 확률과 임계값

`y_prob=0.62`는 모델이 산출한 양성 클래스 확률 추정값입니다. 현재 기준은 0.5이므로 예측은 1입니다. 이 확률이 완벽하게 보정되어 있다는 뜻은 아닙니다.

임계값을 낮추면 일반적으로 더 많은 기사를 인기 기사로 분류하고 재현율을 높일 수 있지만, 잘못 양성으로 분류하는 기사도 늘 수 있습니다. 원래 최종 XGBoost의 0.414와 이번 기준값 0.5는 다른 실험입니다. 두 클래스가 약 50:50이므로 극심한 불균형 때문에 반드시 임계값을 낮췄다고 설명하면 안 됩니다.

## 6. 성능 지표 읽기

- Accuracy: 전체에서 맞힌 비율.
- Precision: 인기 있다고 예측한 기사 중 실제 인기 기사의 비율.
- Recall: 실제 인기 기사 중 찾아낸 비율.
- F1: Precision과 Recall의 조화평균, `2PR/(P+R)`.
- ROC AUC: 여러 임계값에서 두 클래스를 얼마나 잘 구분하는지 보는 지표. 이진 예측값이 아닌 y_prob으로 계산합니다. 0.724를 '정확도 72.4%'라고 읽지 않습니다.

이번 검증 결과:

| 모델 | Accuracy | F1 | ROC AUC |
|---|---:|---:|---:|
| Random Forest | 0.6653 | 0.6685 | 0.7239 |
| XGBoost | 0.6671 | 0.6664 | 0.7243 |

AUC 차이는 약 0.00042로 작고 F1은 RF가 조금 높습니다. 이 한 번의 결과로 XGBoost가 확실히 우수하거나 일반화 능력이 더 좋다고 결론내리지 않습니다.

## 7. test 예측과 test 성능은 다르다

검증은 train 일부를 숨겨 정답과 비교하는 과정입니다. 이후 전체 train으로 다시 학습해 test의 예측을 생성했습니다. test에는 정답이 없으므로 9,515개 예측 파일을 만들었다고 test Accuracy를 알 수 있는 것은 아닙니다. 현재 GitHub에 기록한 점수는 모두 검증 점수입니다.
